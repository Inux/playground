### Resource Interactions
- **Biomass** needs Water + Energy to grow
- **Energy** production consumes Minerals, requires Atmosphere
- **Atmosphere** generated by Biomass, consumed in water cycle
- **Temperature** regulated by Atmosphere, affects water evaporation
- Creates emergent gameplay requiring active management

### Performance Optimizations
- Vertex color baking (lighting calculated once at mesh generation)
- Particle pooling (200 max, reuse inactive)
- Terrain chunking (5×5 grid, 25-50 draw calls)
- Resource updates: O(1) per planet

## Lessons Learned

### Zig 0.15.2 Specifics
- ArrayList requires manual struct init (no `.init()`)
- `deinit()` and `append()` need allocator parameter
- `@alignCast` required for pointer casts
- Return values must be used or assigned to `_`

### Design Decisions
- Vertex colors over shader lighting (simpler, faster for this scale)
- Particle pooling over dynamic allocation (consistent performance)
- Resource dependencies create emergent gameplay without complex AI

### What Went Well
- Modular architecture made adding systems easy
- Test-first approach caught edge cases early
- Resource system design extensible for future features
- User feedback clear and immediate
